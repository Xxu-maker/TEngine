# 2026-09-09 Unity 2022.3 包依赖兼容问题

## 问题现象

使用 Unity 2022.3.14f1c1 打开 TEngine 工程时，脚本编译中断：

```text
error CS0246: The type or namespace name 'TMPro' could not be found
error CS0246: The type or namespace name 'TextMeshPro' could not be found
error CS0246: The type or namespace name 'TMP_Text' could not be found
```

`TEngine.Runtime` 编译失败后，`GameProto`、`GameLogic` 和 `Assembly-CSharp` 也没有生成，Unity 控制台会表现为大量连锁报错。

同时，包管理器还会报告：

```text
com.unity.modules.accessibility@1.0.0 cannot be found
```

## 根本原因

当前 TEngine 分支的 `Packages/manifest.json` 使用了偏新版本 Unity 的包组合：

- `com.unity.ugui` 为 `2.0.0`；
- 缺少 TEngine 本地化模块依赖的 `com.unity.textmeshpro`；
- 包含 Unity 6 才提供的 `com.unity.modules.accessibility`。

Unity 2022.3 的内置 UGUI 版本是 `1.0.0`，TextMeshPro 需要单独安装 `3.0.6`，并且没有 `com.unity.modules.accessibility` 内置模块。

## 正确修复

在 `UnityProject/Packages/manifest.json` 中使用 Unity 2022.3 兼容配置：

```json
"com.unity.textmeshpro": "3.0.6",
"com.unity.ugui": "1.0.0",
```

并移除：

```json
"com.unity.modules.accessibility": "1.0.0",
```

修改后由 Unity 重新解析包并重新生成 `Packages/packages-lock.json`。

## 验证方式

使用 Unity 2022.3.14f1c1 执行批处理编译：

```bash
/Applications/Unity/Hub/Editor/2022.3.14f1c1/Unity.app/Contents/MacOS/Unity \
  -batchmode \
  -quit \
  -projectPath /path/to/TEngine/UnityProject \
  -logFile /tmp/tengine-unity-compile-clean.log
```

最终日志应满足：

- 没有 `error CS`；
- `Tundra build success`；
- `Library/ScriptAssemblies/TEngine.Runtime.dll`、`GameLogic.dll`、`GameProto.dll` 和 `Assembly-CSharp.dll` 均已生成；
- `Exiting batchmode successfully now!`。

## 建议修正

如果项目继续使用 Unity 2022.3，应长期保留上述包版本组合；如果后续升级到 Unity 6，再统一调整 UGUI、TextMeshPro 和 accessibility 模块，避免在不同 Unity 版本之间混用包清单。
